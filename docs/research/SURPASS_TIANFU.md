# 超越天府：全方位分析与改进记录（2026-10-11）

用户要求：天府 Agent（https://tianfu-ai.com/chat）有的功能玄枢都要有，并且在视觉、交互、可信度等各方面超过它。本文记录这一轮分析的依据、结论和已经落地的改动，并列出下一步。

依据只有三类：天府和 DestinyLinker 的公开页面与公告、第三方收录页、玄枢自己的代码与浏览器实测。没有登录、抓取或逆向天府；robots.txt 禁止抓取的页面（天府帮助中心、x.com 帖子等）一律跳过。具体来源见 `TIANFU_PARITY.md`。

## 1. 结论

1. **功能清单已经对齐。** 天府最后一次公开公告是 2025-11-01，之后公开宣称的新功能（奇门、合盘、择日择时、Life Path）玄枢都已具备，见 `TIANFU_PARITY.md`。继续比“有没有”已经拉不开差距。
2. **差距在体验和可信度。** 天府公开可见的卖点是“可视化推理、透明可追溯、拒绝模板化结论”。它的盘面样式、是否流式输出、能否分享或导出 PDF、有没有追问建议，公开资料里都看不到。玄枢在这些方面做到可验证的领先：代码开源，每次工具调用都带 SHA-256，可以在本机复现。
3. **这一轮的改进集中在三处**：视觉重做、对话体验、命盘交互深度（紫微运限、时辰不详、农历输入）。另外按体检结果修了无障碍和移动端问题。

## 3. 体检发现与处理

体检覆盖界面、交互、无障碍和性能，按严重程度分级。

**P0（已全部修复）**
- 在对话页点“生成命盘”后界面没有任何变化：现在自动切到四柱八字并播报。
- 对话未启用时首页是一片禁用控件：改为说明卡片，并提供“先看我的四柱八字”。
- 手机上要滚过整张表单才能看到结果：表单折叠为一行摘要，生成后自动收起。
- 模型回答以原始 Markdown 显示：改为安全的 DOM 渲染（从不使用 innerHTML）。
- 等待回答时切换档案，回答会落进另一个档案的对话：现在切换即中止请求，回答只回到原对话。

**P1（已修复）**
- 失败的回答会被当作上下文再发给模型：错误消息和对应提问不再进入模型上下文。
- 没有流式、停止和超时：已补齐，停止时保留已写出的部分。
- 每次重绘丢失焦点和展开状态：`render()` 统一保存并恢复。
- 标签页缺 id 与 tabpanel 关联：已补；初次加载也设置正确的选中状态。
- 常用标签：加入四化飞星、大运干支，移出可选的专业紫微；移除 ENGINE DEV 徽章。
- 对比度：深色主题四化徽章改深色文字，浅色主题五行色和金色加深，`--faint` 和控件边框达标。
- 字号过小：9–10.5px 统一提到 11px，11px 提到 12px。
- 删除档案没有确认：已加确认。
- 进度提示用红色：新增 `progress` 与 `ok` 两种提示样式。
- 奇门只能用出生时间起局：已加起局时刻选择。
- 文案里的“左侧”在手机上不成立：统一改为“出生资料”。

**代码审查后的修正**
- OpenAI 兼容接口（DeepSeek、通义等）同样流式输出，停止时立即关闭上游连接。
- “不知道出生时辰”随档案保存；AI 对话会收到这一标记，系统提示要求只依据不随时辰变化的内容，置信度按全天误差计算；分享卡片隐藏时柱和紫微部分，JSON 导出带上标记；出生时间起奇门时给出提示。
- 十二时辰对照在真太阳时下按有效时间取样，每行名称取自引擎实际排出的时辰，钟表时间列显示真正要输入的时间。
- 紫微默认流年取自历法引擎的当日农历年，不再用固定的 2 月 20 日估算。
- 奇门换起局时刻后旧盘立即作废，不会把别的时刻的盘当成当前盘。
- 保存对话时，失败或中止的回答连同它的提问一起略去。
- 首页“出生资料不上传”与实际不符（计算需要发到服务器），改为“只用于当次计算，服务器不保存”。

**P2（部分处理）**
- 已处理：空状态加操作按钮；Ctrl+K 不再抢占文本框；去掉对话区的平滑滚动；页脚文字随 `--faint` 一起提亮。
- 第二批已处理：页面与静态资源 gzip，`Cache-Control: no-cache` 加 ETag 校验缓存。
- 留待后续：按需加载翻译表。

## 4. 第二批（已完成）

- **四柱反查**：给出年月日柱（时柱可选），列出 1901–2099 年间所有对得上的出生时段。反查直接调用排盘用的同一个四柱函数，边界逐秒校准，结果与排盘完全一致；天干组合不合五虎遁、五鼠遁时说明不可能，不做无效搜索。每个时段可一键排盘。
- **命盘导入核对**：粘贴其他软件的命盘（简体或繁体），识别四柱、命宫、身宫、五行局、命主身主、各宫主星和生年四化，逐项比对。有差异时，用常见的规则差异（23:00 换日、闰月归属、平太阳时或真太阳时、扣除夏令时，以及两两组合）重算，指出哪套规则能完全复现对方的盘，并可一键套用。天府的公开说明建议“不要粘贴外部命盘数据”，玄枢把这件事做成了核验工具。
- **大运流年时间条**：四柱下方横排大运，点选展开十年流年，点某一年直接打开紫微盘的同年流年层，把八字和紫微的时间轴连起来。
- **性能**：页面与静态资源压缩约八成，未改动的文件只返回 304。

## 5. 第三批（已完成）

- **今日历法**：按本机时间列出今天的四柱、农历、所在节气与到下一节气的进度条、建除值日和月相图（附下次满月、新月）。生成命盘后，再列出今天四柱对日主的十神、与本命四支的六冲六合同支，以及当前大运。页首一行今日提示，点开即是完整卡片。天府的每日内容需要登录且不公开；玄枢不打吉凶分，每个字段都能追溯到确定性工具，AI 对话也能调用。
- **性能**：English、日本語与繁體的翻译表只在切换语言时下载，简体中文首屏少下载约 245 KB。
- **细节**：配色按钮图标改用 CSS 绘制（部分系统字体缺 ◐☀☾ 会显示成方块）；英文界面的工具计数、时基摘要、标题空格修正。

## 6. 第四批（已完成）

- **多人关系**：从当前命盘、本机档案和页面上临时添加的成员里选 2 到 8 人（家人、团队、朋友），一次列出：成员卡（四柱、生肖、日主）；SVG 关系图，可按天干五合、六合、六冲、六害、相刑、同支筛选，点成员只看他的线，点线打开这一对的明细；日干十神矩阵（行看列，A 看 B 与 B 看 A 分开列）；两两明细表；成员之间凑齐的年支或日支三合；全体五行分布与各五行的日主成员。时辰不详的成员不参与时柱比较。天府公开的是双人合盘；玄枢把关系扩展到多人，同样不打匹配分，AI 对话的八字专家也能调用。
- **今日历法选日期**：卡片上可以选任意日期和时刻，前一天、后一天逐日翻看，一键回到此刻；页面开着时每到整点自动刷新，切回页面也会刷新。

## 7. 第五批（已完成）

- **规则差异对照**：同一份出生资料换用各家常见规则（23:00 换日、闰月归属、平太阳时或真太阳时、扣除夏令时，以及两两组合）逐一重排，一张表标出四柱、农历、命宫、身宫、五行局、命宫主星和生年四化里哪些格子会变；顶部汇总“几种规则下完全相同”“哪些字段不受影响”“哪些字段会变、被几种规则改变”，并提示出生离交节很近、23:00 后出生、闰月、夏令时等情况，任一方案一键套用。天府宣称“三层不确定性”，但公开资料看不到规则差异；玄枢把它摊开成可核对的表，AI 对话的每位专家都能调用。
- **节气与月相日历**：ICS 在二十四节气之外加入新月、上弦、满月、下弦，历法日历页与今日历法卡片一键下载，可导入手机日历。

## 8. 第六批（已完成）

- **可复现的计算评测**：天府作者公开的 MingLi-Bench 是命理选择题（答案来自命理师大赛题库，数据未注明许可），测的是解读是否“猜中”，玄枢不对预测准确率做声明，也不转载那套题。玄枢评测的是可以客观核对的部分：1901–2099 年每一天的农历日期与四柱、4,776 个节气和 9,845 个月相时刻、3,000 个随机紫微盘，逐项对照 sxtwl（寿星天文历）、lunar_python、lunardate、PyEphem、iztro-py。脚本、固定版本和原始数据都在 `docs/evals/`，任何人都能重跑；工作台页首和页脚的「计算核验」弹窗直接展示结果和每一处剩余差异的原因。
- **评测查出的问题已修正**：1914、1916、1920 年各有一个月，玄枢的初一比三家参考都晚一天。原因是 1912–1928 年的历书按北京地方平时（东经 116°25′）编算（Aslaksen, *The Mathematics of the Chinese Calendar*），玄枢原来一律用东经 120°。修正后这三个月全部一致；剩下的差异是 2057、2097 年朔离午夜 1–2 分钟（取决于未来 ΔT）和 lunardate 的查表差异。

## 9. 下一步

以下方向都能用公开规则或玄枢自己的数据实现，不需要天府的任何非公开内容：

1. **多人关系的延伸**：成员笔记、把多人关系结果带进 AI 对话作为上下文。
2. **紫微晚子时选项**：评测显示 iztro 把 23:00–23:59 算作次日农历日，玄枢紫微按当日；可以作为一条规则选项，并加进规则差异对照。
3. **四化表流派**：找到可引用的规则来源和样本盘后，在规则差异对照里加入不同四化表。

钦天四化、北派等流派扩展仍然只在找到可引用的规则来源和样本盘之后再做，不凭印象编写。
