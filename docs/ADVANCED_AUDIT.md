# 当前开发阶段 深度改造审计

## 重点价值

最初实现缺少八字传统大运，出生时间不确定时也只在固定采样点排盘，采样间隙可能漏掉实际计算边界。本轮通过 `app/advanced.py` 增加真实规则计算以及事件驱动时间分区，并在 `app/report.py` 形成可选联合证据链。

## 算法与验证

- `dayun_sequence`：从本命立春年柱的天干阴阳判顺逆，从月柱沿 60 甲子递增／递减；与上一／下一十二节**实际 UTC 时刻**作差，以三日一岁计算名义年龄。独立规则样本：1990-06-15，庚午年壬午月，男顺排癸未→甲申→乙酉→丙戌，女逆排辛巳→庚辰→己卯→戊寅。参考 `https://www.yilibazi.com/baike/dayun.html`、`https://www.aizhanxing.com/wiki/eastern/bazi-timing.html`。
- `birth_boundary_map`：IANA 时区全部先换算为真实 UTC 瞬间，用有效传统时辰/日界状态和历史 UTC offset 作分钟间隔探测、二分求根至整秒；十二节由 Swiss Ephemeris 计算精确交节时刻并直接加入；区间中点复用既有 `calculate_bazi` / `calculate_ziwei`。测试含白露 ±10 分钟交节、2000-08-16 01:00 时辰、2024-02-10 23:00 子初换日、罗马 2024-03-31 DST 跳变和 2024-10-27 DST 回拨。
- 额外在 REST、2025/2026 MCP、stdio、CLI、Web 以及 Markdown 报告实现相同结构化响应或组合选择；OpenAPI 自动声明请求约束。

## 仍然存在的局限

1. **精度区别**：所谓秒级定位仅是当前模型离散边界的数值时间；天文学计算/历史历表有误差，用户出生记录不能反推出秒精度。边界地图只审计现有八字与部分紫微；未实现的星曜、流派及中气黄历规则可能产生额外切换。
2. **大运口径**：流派可采用不同的换日、起运进位、性别/方向判断和历法年份。公历投影默认每名义年龄 365.2425 日，是便于显示的连续均值年近似，**不是**权威交运日。
3. **重大未完成项**：完整奇门遁甲、紫微全星系/运限、多流派一致性验证、生产 OAuth、远程 MCP 客户端互操作、公网 HTTPS 服务；不会因为本地单元测试通过而声称完成。
4. **前端隐私**：本地档案存 localStorage 明文，仅加密备份采用 AES-GCM。公开多用户环境应实现登录、细粒度授权、可审计的隐私管理与删除机制。
5. **测试环境**：Chromium 是真实浏览器，API 由 Python TestClient 桥接；独立 Uvicorn 测试是本机 TCP，并非跨公网 TLS/CORS/反向代理/原生 ChatGPT 或 Claude Plugin 认证。Dockerfile 在 CI 配置构建，但当前云端未有 Docker daemon，故不能宣称通过 Docker 实测。
